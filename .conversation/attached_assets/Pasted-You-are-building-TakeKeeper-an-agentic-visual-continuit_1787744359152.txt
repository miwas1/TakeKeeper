You are building **TakeKeeper**, an agentic visual continuity supervisor for film crews.

The core product promise is:

**Know what changed before you roll again.**

TakeKeeper allows a filmmaker to capture an approved visual reference for a scene, capture a later take, use Gemini to identify continuity differences, let the filmmaker approve or fix changes, and remember approved changes for future takes.

This project is being built for the **Replit track of the Agentic Cinema Hackathon**.

For this phase, focus ONLY on the technical foundation and architecture. Do not build the full AI continuity workflow yet.

# Phase 1 Goal

Create a clean, production-ready foundation that all later TakeKeeper features can safely build upon.

At the end of this phase, the application should:

* run successfully on Replit;
* have a responsive web application foundation;
* have a clean TypeScript architecture;
* have a professional TakeKeeper design system;
* connect successfully to persistent PostgreSQL storage;
* have object/media storage architecture ready;
* have Google Cloud / Gemini / ADK configuration prepared;
* have authentication architecture prepared;
* have the complete core database schema;
* have no major placeholder architecture that will need to be rewritten later.

# 6. Google AI / Agent Architecture

Prepare the Google AI architecture without implementing the complete continuity workflow.

Create clear server-side modules for future:

* Script Breakdown Agent
* Visual State Agent
* Continuity Supervisor Agent
* Report Agent

The intended production architecture must be:

```text
TakeKeeper on Replit
        ↓
TakeKeeper backend
        ↓
Google Cloud Agent Platform / Agent Engine
        ↓
ADK agents
        ↓
Gemini
        ↓
validated TakeKeeper tools
        ↓
application/database state
```

The model must NEVER directly mutate the database.

Future agent mutations must use this pattern:

```text
Gemini requests tool call
→ backend validates arguments
→ application executes function
→ database changes
→ result returned to agent
```

Create interfaces/placeholders for application tools such as:

* get_scene
* get_continuity_bible
* get_reference_take
* get_previous_approved_changes
* save_observations
* create_issue
* resolve_issue
* approve_state_change
* update_continuity_state
* get_shoot_day_takes
* generate_report

Do not fake agent results.
