# Phase 2 Goal

Build the complete non-AI product shell and core filmmaking workflow around which the later Gemini continuity system will operate.

At the end of this phase, a user should be able to navigate TakeKeeper, create and manage projects/scenes/shots/takes, open the seeded demo project, move through the intended shooting workflow, and understand exactly how the final product will work even though full Gemini continuity analysis is not implemented yet.

The UI must feel like polished filmmaking software rather than a generic generated dashboard.

# Core Product Promise

Everything should reinforce:

**Know what changed before you roll again.**

TakeKeeper is not:

* a chatbot;
* a screenplay generator;
* a generic filmmaking assistant;
* a production-management suite.

It is specifically an **agentic visual continuity supervisor**.

# 15. Intentional Change Dialog

Build the workflow UI now.

When a user selects:

**Intentional**

ask:

**Update continuity from this take?**

Options:

### This shot only

Change applies only to the current shot.

### Rest of scene

Change applies through the remaining scene context.

### From now on

Update the approved state for subsequent relevant takes.

### Cancel

The actual agent reasoning comes later, but user decisions should already map cleanly to the Phase 1 database model.

Persist decisions if real issues exist in the database.

Do not fabricate issues solely to demonstrate the dialog.

No important product state should live only in React/component state.
